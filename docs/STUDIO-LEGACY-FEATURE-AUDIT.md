# Studio 早期换装工作台功能审计

> 本文用于防止将“Next.js 路由已接入”误认为“早期工作台已完整迁移”。状态只按当前源码可见实现判断；没有浏览器实测的交互均不标记为验收通过。

## 产品边界

- **Studio（`/studio`）**：角色中心的换装工作台，负责皮肤、服装穿脱、3D 预览、动作、搭配保存/恢复和文件导入导出。
- **素材库 / 个人衣橱**：素材上传、分类、搜索、作者/来源、收藏和维护。Studio 只消费素材，不承担素材治理。
- 披肩（SHAWL）、外套（COAT）、披风（CAPE）必须独立。披风是背部装备，不合成进标准 64×64 Minecraft 皮肤 PNG。

## 旧 Vite 源码核对结果

旧入口 `src/App.tsx` 使用 `PresetStudio`、`AiSkinStudio` 和 `ThreeCapePreview`。其中：

- `src/PresetStudio.tsx` 有皮肤 PNG 导入、披肩/外套/披风三类预设、Steve/Alex、正/背面、鞘翅切换、日夜/生物群系背景、自定义背景、待机/挥手/行走/飞行动作、视角缩放、PNG/JSON 导出导入、重置及 Blockbench 交接。
- `src/ThreeCapePreview.tsx` 基于 `skinview3d`，使用 `IdleAnimation`、`WalkingAnimation`、`FlyingAnimation` 和挥手自定义动画；支持披风/鞘翅互斥、XYZ 旋转、缩放和背景。
- 旧源码**没有**帽子、裤子、鞋子、眼镜等类别的完整可用素材目录，也没有蹲下、受击、游泳动作实现。不能把需求清单中的设想误记为旧版本已存在功能。
- 旧 Vite 入口中的 AI 皮肤工坊与 Blockbench 编辑器是相邻模块，不应与角色换装工作台混为一谈。

## 验收原则

1. 代码存在不等于交互通过；所有“待浏览器验收”必须通过真实点击、拖动、文件下载和刷新恢复确认。
2. 服装切换只更新共享角色状态，不应刷新整页或重建整个 3D viewer。
3. PNG 必须是 64×64、透明像素保留、可被原版 Minecraft 识别；披风单独导出/管理。
4. 私有素材不可因试穿或保存穿搭而自动公开。
5. 未接入类别必须明确显示空状态，不能用占位图标冒充真实服装素材。
6. 生产发布前必须完成 Next.js build、浏览器 E2E、登录态云端保存/恢复、移动端触控和 Docker 数据库矩阵。
