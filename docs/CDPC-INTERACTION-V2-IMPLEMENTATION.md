# CDPC 完整交互设计 V2：实施任务与验收清单

> 状态：实施基线（不是功能完成声明）
> 基线日期：2026-11-06
> 原则：以当前代码、自动化测试、浏览器验证和生产证据判断完成状态。文档或静态页面存在不代表功能已实现。

## 目标与边界

把用户从进入 CDPC 到完成、保存、导出、发布作品的完整旅程拆成路由、组件、状态和验收任务。先完成 P0 创作闭环，再做 P1 专业编辑能力，最后做 P2 素材与作品生态。

### 不可破坏的产品约束

- 三种入口（从皮肤开始、从服装开始、从完整搭配开始）进入同一项目体系和同一工作台，不创建互不兼容的编辑器。
- 素材中心的普通浏览可以独立预览单件素材；但在衣橱/工作台中，用户执行“选装/试穿/加入搭配”后必须立即更新持续显示的人物预览，不能等到完整搭配模式才渲染人物。默认使用系统人物底模；导入用户 Skin 后替换底模并保留已穿戴装备。添加、替换、隐藏、移除任一装备均实时更新人物。完整搭配模式只增加多件装备的组合管理，不是人物预览的开关。
- 披肩、外套、披风是独立类别和装备槽位；披风与鞘翅分别控制和渲染。
- 素材浏览、单件编辑、完整搭配三种模式切换不丢失项目、选中项、变换参数和搭配状态。
- AI 生成结果进入统一素材体系，不建立孤立的 AI 专用资产格式。
- 正式页面、工作台、编辑器外围 UI 和服务端 API 统一由 Next.js 提供；不再以 Vite 作为用户页面运行时。迁移前盘点并复用现有像素画布/3D 引擎，完成 Next.js 内嵌与回归后移除 Vite 页面入口、构建脚本、插件、依赖和旧 Service Worker 缓存。禁止新增 Vite 页面和跨框架跳转。
- Mantine 作为常规 UI 主组件库，Tailwind CSS v4 管理设计令牌/布局样式，Lucide React 统一图标；避免重复造控件。
- 3D 引擎只负责模型、材质、动画和预览；服务端负责权限、持久化和业务规则。

## P0：必须先完成的创作闭环

### P0.1 路由和进入流程
- [ ] 审计当前所有 Next.js 路由、页面组件、遗留 Vite 页面/入口、重定向、Service Worker、构建脚本和重复实现；确认代码真实引用后再删除旧入口。
- [ ] 首页提供三个清晰创作入口：从皮肤开始、从服装开始、从完整搭配开始。
- [ ] 三个入口创建/打开同一 Project 结构，传递明确的初始工作模式和来源。
- [ ] 支持新建项目、打开项目、恢复最近项目；切换项目时保护未保存修改。
- [ ] 工作台使用精简项目工具栏：返回、项目名、保存状态、撤销/重做、导入、导出、更多操作。
- [ ] 刷新、深链接、浏览器前进/返回后恢复项目和工作模式，不丢失状态。

### P0.2 统一数据契约
### P0.2A 数据所有权、文件存储与生命周期（新增验收项）
- [ ] 所有 Project、Outfit、Asset、Texture、ExportRecord 均定义 owner/user ID、可见性、来源、授权和服务端访问策略；客户端传入的 ownerId 不作为授权依据。
- [ ] 明确文件存储对象键、MIME/文件签名、大小/像素上限、哈希去重、缩略图生成、病毒/恶意文件检测策略、访问 URL 时效和删除清理队列。
- [ ] 明确软删除/回收站、彻底删除、引用计数与孤儿文件清理；删除用户/项目/素材时不误删其他项目仍引用的资源。
- [ ] 定义并发编辑、版本冲突、幂等保存、重复上传、重复导出和任务重试的行为；所有权与状态转换由服务端事务或等价机制保证。
- [ ] 记录用户素材、公共素材、AI 生成素材、导入素材的来源链和授权快照，禁止把“可预览”推断为“可商用/可再分发”。

- [ ] 明确 Project、ProjectVersion、Asset、AssetVersion、Texture、Outfit/Slot、ExportRecord 的 schema、关系、索引和迁移策略。
- [ ] Project 至少记录 owner、项目类型、名称、封面、当前版本、更新时间、归档/删除状态。
- [ ] Asset 至少记录唯一 ID、名称/类别、作者/来源、纹理引用/尺寸、模型适配、穿戴位置、默认变换、授权、审核状态和版本。
- [ ] 区分编辑内存状态、本地恢复状态、云端保存状态、版本快照、素材审核状态和作品发布状态，禁止混用单一 status。
- [ ] 项目中的素材引用使用稳定 ID 和版本；记录授权快照/来源，避免公共素材更新后项目静默变化。
- [ ] AI 生成资产走统一入库、校验、预览、编辑和导出流程。

### P0.3 三种工作模式
- [ ] 素材浏览：分类、搜索、筛选、单件预览和加入搭配。
- [ ] 单件编辑：编辑单件服装；导入 Skin 后显示人物底模和当前单件。
- [ ] 完整搭配：显示人物、基础 Skin、所有装备及独立披风/鞘翅状态。
- [ ] 浏览→单件编辑保留选中素材；单件编辑→搭配写入正确槽位；搭配→单件编辑恢复当前选中项。
- [ ] 切换分类不重置人物、项目、选区和搭配。
- [ ] 切换项目/关闭页面时检测脏状态并提供保存、放弃、取消。

### P0.4 素材中心与装备槽位
- [ ] 分类：披肩、外套、上衣、裤子、鞋子、帽子、披风、其他配件。
- [ ] 筛选：名称/标签/作者、类型、风格、颜色、来源、排序。
- [ ] 卡片：单击预览、收藏、加入对应槽位、详情/复制/举报；手机端提供显式操作，不依赖双击或右键。
- [ ] 状态：骨架屏、空素材、无搜索结果、加载失败/重试、素材失效、权限不足、已删除、审核中。
- [ ] 槽位：Skin、披肩、外套、上衣、裤子、鞋子、帽子、披风、鞘翅；每个槽位定义数量、兼容性和替换策略。
- [ ] 操作：添加、替换、移除、隐藏、图层、复制/粘贴参数、锁定、重置。
- [ ] 清空搭配二次确认；移除单件不弹窗并可撤销。
- [ ] 冲突检测只提示和提供修复建议，不静默删除服装；覆盖位置冲突、穿透、模型不兼容、纹理尺寸不兼容、披风/鞘翅重叠。

### P0.5 属性面板和 3D
- [ ] 人物预览是衣橱/试穿工作流的常驻主视图：无 Skin 时显示默认人物，有 Skin 时显示导入人物；选中并试穿单件即刻穿到人物上，切换分类不清空穿戴。
- [ ] 素材中心“查看素材”和工作台“试穿/加入搭配”语义分离；在工作台中选装动作不要求用户再切换到“完整搭配”模式才看到人物。
- [ ] 验收 Classic/Slim 手臂、内层/外层皮肤、遮挡顺序、透明像素、部位映射、穿透与碰撞；不兼容时明确提示且不得静默丢弃。
- [ ] 披肩、外套、披风必须是不同资产类型/渲染层/槽位；披风和鞘翅独立显示、隐藏、变换与动画。披风应向角色后方自然摆动，飞行时与鞘翅姿态协调。
- [ ] 旋转支持连续 360° 的 XYZ 操作；相机控制不得出现 180° 锁死、突跳或过度阻尼；动作切换和视角切换各自只有一个紧凑入口。
- [ ] 属性分为基础、变换、渲染区；XYZ 位置/旋转/缩放支持数值输入和滑块。
- [ ] 可见性、图层、格式支持时的透明度、模型适配和渲染质量可操作。
- [ ] 动作切换为一个紧凑入口，视角切换为一个紧凑入口；不堆叠按钮，不强制二级菜单。
- [ ] 单件/完整搭配采用各自预览规则；切换模式时不丢失 3D 状态。
- [ ] 引擎初始化失败、WebGL 不支持、Skin 格式错误、纹理不兼容、资源失效均有页面内说明、重试或降级。

### P0.6 保存、项目管理和导出
- [ ] 定义导出兼容性矩阵：标准 Minecraft Skin PNG（64×64、透明度/UV/Classic-Slim 校验）、CDPC 服装/配件纹理、披风纹理、鞘翅纹理、Outfit JSON、项目备份分别校验和说明。
- [ ] 明确哪些服装像素会合成进 Skin PNG，哪些资源必须作为独立纹理/游戏资源；披风/鞘翅不得被误称为已写入标准 Skin PNG，官方 Mojang/Microsoft 披风不包含在导出中。
- [ ] 导出页面说明目标游戏版本、模型类型、所需安装方式/资源包或服务端支持；不兼容的格式不显示为可直接使用。
- [ ] Ctrl/Cmd+S、撤销/重做、自动保存防抖/批量更新、保存中/成功/失败反馈。
- [ ] 本地恢复数据与云端正式项目分离；保存使用版本校验和幂等策略。
- [ ] 网络断开时保留编辑状态；恢复连接后同步并处理冲突，不覆盖新版本。
- [ ] 项目支持新建、打开、重命名、复制、归档、回收站删除/恢复、备份导入导出、版本历史。
- [ ] 版本恢复先预览，恢复后创建新版本，不覆盖历史快照。
- [ ] 导出中心支持 Skin PNG、单件素材 PNG、搭配 JSON、预览图片、完整项目备份。
- [ ] 各格式独立校验尺寸、透明度、UV/模型、素材引用和授权；不得把搭配预览图误当成原版 Skin PNG。
- [ ] 导出前预览、生成进度、成功结果、失败原因和重试路径完整。

### P0.7 Next.js PWA 与 SWC 构建边界
- [ ] Next.js 是唯一页面运行时；SWC 负责编译/转译，不等同于 PWA，也不能替代 Service Worker。
- [ ] PWA 使用与 Next.js 路由匹配的 manifest、图标、Service Worker 和安装体验；静态资源可缓存，登录态 API、私有项目、AI 结果和用户文件默认不得被公共缓存。
- [ ] 明确离线能力范围：可离线打开壳层/本地草稿不代表云端保存成功；恢复网络后执行冲突检测与同步。
- [ ] 发布时采用带版本号的缓存策略、更新提示和旧缓存清理；验证新镜像上线后不会继续加载旧 Vite/PWA 资源或出现 HTML/JS 版本错配。
- [ ] 验收首次安装、更新、离线、重新联网、退出登录、账号切换和 Service Worker 清理；不允许 Service Worker 缓存跨用户私有数据。

## 路由级验收矩阵

| 路由 | 关键验收旅程 |
|---|---|
| / | 三种入口、最近项目、恢复项目 |
| /ai | 文生图/图生图、生成状态、结果入库、进入编辑 |
| /editor | Skin/纹理导入、单件编辑、撤销重做、导出 |
| /studio?mode=wardrobe | 人物底模持续显示、选装即试穿、槽位穿戴、披肩/外套/披风独立、鞘翅独立 |
| /studio | 项目打开、三模式切换、保存、版本、导出 |
| /studio?mode=ai | 生成结果绑定当前项目 |
| /studio?mode=edit | 单件编辑与纹理数据同步 |
| /studio?mode=outfit | 完整搭配、冲突检测、槽位规则 |
| /me/creator | 个人作品/素材/审核状态 |
| /@username 或 /@username/:slug | 创作者公开主页/作品详情、分享、授权、举报 |
| /admin 及子路由 | 服务端授权、用户/素材/审核/统计真实数据 |

> 路由清单是目标契约，不代表所有路由当前都已存在。`/studio` 是唯一创作工作台；`/me/*` 是登录用户的私有个人空间；`/@username/*` 是公开创作者空间。旧 `/workbench`、`/wardrobe`、`/dress-up`、`/creator` 等路径仅在确认历史链接和业务语义后做兼容重定向，并保留 mode/project 参数；不得同时维护两套工作台。

## 测试与发布门槛

每一阶段均须满足：
- 单元/集成测试覆盖数据模型、槽位规则、变换、保存版本和导出校验。
- 浏览器 E2E 覆盖首页入口→选素材→单件编辑→加入搭配→调整→保存→导出的完整旅程。
- 响应式覆盖 320、375、768、1024、1440px。
- 验证登录态、普通用户/创作者/管理员权限边界。
- Next.js 生产构建、Docker 镜像构建和关键路由 smoke test 通过。
- 测试失败/网络断开/云端冲突/资源删除/权限不足等恢复路径。
- 未运行测试明确标记为“未验证”；不能以页面截图、文档或静态 UI 代替测试证据。

## 实施顺序

1. 审计当前 Next.js 路由、Vite 遗留入口、Prisma schema/migrations、项目保存能力、3D 工作台、CI 和部署入口。
2. 建立统一数据契约和状态机，先补齐 P0 最小闭环。
3. 逐路由迁移到 Next.js，每次迁移均验证功能和深链接；确认无依赖后再移除 Vite 入口。
4. P0 完成并通过测试后实施 P1，再实施 P2。
5. 每个 PR 只处理可独立验收的一组能力；不以大规模覆盖式重写代替增量迁移。
