# CDPC 完整交互设计 V2：实施任务与验收清单

> 状态：实施基线（不是功能完成声明）
> 基线日期：2026-11-06
> 原则：以当前代码、自动化测试、浏览器验证和生产证据判断完成状态。文档或静态页面存在不代表功能已实现。

## 目标与边界

把用户从进入 CDPC 到完成、保存、导出、发布作品的完整旅程拆成路由、组件、状态和验收任务。先完成 P0 创作闭环，再做 P1 专业编辑能力，最后做 P2 素材与作品生态。

### 不可破坏的产品约束

- 三种入口（从皮肤开始、从服装开始、从完整搭配开始）进入同一项目体系和同一工作台，不创建互不兼容的编辑器。
- 素材中心的普通浏览可以独立预览单件素材；但在衣橱/工作台中，用户执行“选装/试穿/加入搭配”后必须立即更新持续显示的人物预览，不能等到完整搭配模式才渲染人物。默认使用系统人物底模；导入用户 Skin 后替换底模并保留已穿戴装备。添加、替换、隐藏、移除任一装备均实时更新人物。完整搭配模式只增加多件装备的组合管理，不是人物预览的开关。
- 披肩、外套、披风是独立类别和装备槽位；披风与鞘翅分别控制和渲染。
- 素材浏览、单件编辑、完整搭配三种模式切换不丢失项目、选中项、变换参数和搭配状态。
- AI 生成结果进入统一素材体系，不建立孤立的 AI 专用资产格式。
- 正式页面、工作台、编辑器外围 UI 和服务端 API 统一由 Next.js 提供；不再以 Vite 作为用户页面运行时。迁移前盘点并复用现有像素画布/3D 引擎，完成 Next.js 内嵌与回归后移除 Vite 页面入口、构建脚本、插件、依赖和旧 Service Worker 缓存。禁止新增 Vite 页面和跨框架跳转。
- Mantine 作为常规 UI 主组件库，Tailwind CSS v4 管理设计令牌/布局样式，Lucide React 统一图标；避免重复造控件。
- 3D 引擎只负责模型、材质、动画和预览；服务端负责权限、持久化和业务规则。

## P0：必须先完成的创作闭环

### P0.1 路由和进入流程
- [ ] 审计当前所有 Next.js 路由、页面组件、遗留 Vite 页面/入口、重定向、Service Worker、构建脚本和重复实现；确认代码真实引用后再删除旧入口。
- [ ] 首页提供三个清晰创作入口：从皮肤开始、从服装开始、从完整搭配开始。
- [ ] 三个入口创建/打开同一 Project 结构，传递明确的初始工作模式和来源。
- [ ] 支持新建项目、打开项目、恢复最近项目；切换项目时保护未保存修改。
- [ ] 工作台使用精简项目工具栏：返回、项目名、保存状态、撤销/重做、导入、导出、更多操作。
- [ ] 刷新、深链接、浏览器前进/返回后恢复项目和工作模式，不丢失状态。

### P0.2 统一数据契约
### P0.2A 数据所有权、文件存储与生命周期（新增验收项）
- [ ] 所有 Project、Outfit、Asset、Texture、ExportRecord 均定义 owner/user ID、可见性、来源、授权和服务端访问策略；客户端传入的 ownerId 不作为授权依据。
- [ ] 明确文件存储对象键、MIME/文件签名、大小/像素上限、哈希去重、缩略图生成、病毒/恶意文件检测策略、访问 URL 时效和删除清理队列。
- [ ] 明确软删除/回收站、彻底删除、引用计数与孤儿文件清理；删除用户/项目/素材时不误删其他项目仍引用的资源。
- [ ] 定义并发编辑、版本冲突、幂等保存、重复上传、重复导出和任务重试的行为；所有权与状态转换由服务端事务或等价机制保证。
- [ ] 记录用户素材、公共素材、AI 生成素材、导入素材的来源链和授权快照，禁止把“可预览”推断为“可商用/可再分发”。

- [ ] Project 至少记录 owner、项目类型、名称、封面、当前版本、更新时间、归档/删除状态。
- [ ] Asset 至少记录唯一 ID、名称/类别、作者/来源、纹理引用/尺寸、模型适配、穿戴位置、默认变换、授权、审核状态和版本。
- [ ] 区分编辑内存状态、本地恢复状态、云端保存状态、版本快照、素材审核状态和作品发布状态，禁止混用单一 status。
- [ ] 项目中的素材引用使用稳定 ID 和版本；记录授权快照/来源，避免公共素材更新后项目静默变化。
- [ ] AI 生成资产走统一入库、校验、预览、编辑和导出流程。

### P0.3 三种工作模式
- [ ] 素材浏览：分类、搜索、筛选、单件预览和加入搭配。
- [ ] 单件编辑：编辑单件服装；导入 Skin 后显示人物底模和当前单件。
- [ ] 完整搭配：显示人物、基础 Skin、所有装备及独立披风/鞘翅状态。
- [ ] 浏览→单件编辑保留选中素材；单件编辑→搭配写入正确槽位；搭配→单件编辑恢复当前选中项。
- [ ] 切换分类不重置人物、项目、选区和搭配。
- [ ] 切换项目/关闭页面时检测脏状态并提供保存、放弃、取消。

### P0.4 素材中心与装备槽位
- [ ] 分类：披肩、外套、上衣、裤子、鞋子、帽子、披风、其他配件。
- [ ] 筛选：名称/标签/作者、类型、风格、颜色、来源、排序。
- [ ] 卡片：单击预览、收藏、加入对应槽位、详情/复制/举报；手机端提供显式操作，不依赖双击或右键。
- [ ] 状态：骨架屏、空素材、无搜索结果、加载失败/重试、素材失效、权限不足、已删除、审核中。
- [ ] 槽位：Skin、披肩、外套、上衣、裤子、鞋子、帽子、披风、鞘翅；每个槽位定义数量、兼容性和替换策略。
- [ ] 操作：添加、替换、移除、隐藏、图层、复制/粘贴参数、锁定、重置。
- [ ] 清空搭配二次确认；移除单件不弹窗并可撤销。
- [ ] 冲突检测只提示和提供修复建议，不静默删除服装；覆盖位置冲突、穿透、模型不兼容、纹理尺寸不兼容、披风/鞘翅重叠。

### P0.5 属性面板和 3D
- [ ] 人物预览是衣橱/试穿工作流的常驻主视图：无 Skin 时显示默认人物，有 Skin 时显示导入人物；选中并试穿单件即刻穿到人物上，切换分类不清空穿戴。
- [ ] 素材中心“查看素材”和工作台“试穿/加入搭配”语义分离；在工作台中选装动作不要求用户再切换到“完整搭配”模式才看到人物。
- [ ] 验收 Classic/Slim 手臂、内层/外层皮肤、遮挡顺序、透明像素、部位映射、穿透与碰撞；不兼容时明确提示且不得静默丢弃。
- [ ] 披肩、外套、披风必须是不同资产类型/渲染层/槽位；披风和鞘翅独立显示、隐藏、变换与动画。披风应向角色后方自然摆动，飞行时与鞘翅姿态协调。
- [ ] 旋转支持连续 360° 的 XYZ 操作；相机控制不得出现 180° 锁死、突跳或过度阻尼；动作切换和视角切换各自只有一个紧凑入口。
- [ ] 属性分为基础、变换、渲染区；XYZ 位置/旋转/缩放支持数值输入和滑块。
- [ ] 可见性、图层、格式支持时的透明度、模型适配和渲染质量可操作。
- [ ] 动作切换为一个紧凑入口，视角切换为一个紧凑入口；不堆叠按钮，不强制二级菜单。
- [ ] 单件/完整搭配采用各自预览规则；切换模式时不丢失 3D 状态。
- [ ] 引擎初始化失败、WebGL 不支持、Skin 格式错误、纹理不兼容、资源失效均有页面内说明、重试或降级。

### P0.6 保存、项目管理和导出
- [ ] 定义导出兼容性矩阵：标准 Minecraft Skin PNG（64×64、透明度/UV/Classic-Slim 校验）、CDPC 服装/配件纹理、披风纹理、鞘翅纹理、Outfit JSON、项目备份分别校验和说明。
- [ ] 明确哪些服装像素会合成进 Skin PNG，哪些资源必须作为独立纹理/游戏资源；披风/鞘翅不得被误称为已写入标准 Skin PNG，官方 Mojang/Microsoft 披风不包含在导出中。
- [ ] 导出页面说明目标游戏版本、模型类型、所需安装方式/资源包或服务端支持；不兼容的格式不显示为可直接使用。
- [ ] Ctrl/Cmd+S、撤销/重做、自动保存防抖/批量更新、保存中/成功/失败反馈。
- [ ] 本地恢复数据与云端正式项目分离；保存使用版本校验和幂等策略。
- [ ] 网络断开时保留编辑状态；恢复连接后同步并处理冲突，不覆盖新版本。
- [ ] 项目支持新建、打开、重命名、复制、归档、回收站删除/恢复、备份导入导出、版本历史。
- [ ] 版本恢复先预览，恢复后创建新版本，不覆盖历史快照。
- [ ] 导出中心支持 Skin PNG、单件素材 PNG、搭配 JSON、预览图片、完整项目备份。
- [ ] 各格式独立校验尺寸、透明度、UV/模型、素材引用和授权；不得把搭配预览图误当成原版 Skin PNG。
- [ ] 导出前预览、生成进度、成功结果、失败原因和重试路径完整。

### P0.7 Next.js PWA 与 SWC 构建边界
- [ ] Next.js 是唯一页面运行时；SWC 负责编译/转译，不等同于 PWA，也不能替代 Service Worker。
- [ ] PWA 使用与 Next.js 路由匹配的 manifest、图标、Service Worker 和安装体验；静态资源可缓存，登录态 API、私有项目、AI 结果和用户文件默认不得被公共缓存。
- [ ] 明确离线能力范围：可离线打开壳层/本地草稿不代表云端保存成功；恢复网络后执行冲突检测与同步。
- [ ] 发布时采用带版本号的缓存策略、更新提示和旧缓存清理；验证新镜像上线后不会继续加载旧 Vite/PWA 资源或出现 HTML/JS 版本错配。
- [ ] 验收首次安装、更新、离线、重新联网、退出登录、账号切换和 Service Worker 清理；不允许 Service Worker 缓存跨用户私有数据。

| 路径 | 唯一职责 |

| / | 首页与创作入口 |
| /ai | AI 皮肤生成 |
| /editor | 单张皮肤/纹理编辑 |
| /studio | 唯一换装、试穿、搭配与项目工作台 |

- /studio 是创作工具，不是个人主页；保存后的项目归属当前用户。
- /u/[username]/wardrobe 展示用户保存且允许公开的穿搭；编辑操作回到 /studio 并加载原项目。
- 素材选择器属于 Studio 内部工作流；用户公开素材页属于用户空间，不维护第二套编辑状态。
- 所有权和授权一律以数据库内部不可变 userId 为准，不能以 URL username 或客户端传入 ownerId 作为授权依据。
- username 采用小写规范化 slug，建议 3–24 位 ASCII 字母/数字/连字符；数据库唯一约束、保留名、旧 slug 历史和永久重定向必须一并实现。保留名至少包括 ai、editor、studio、creator、admin、api、u、outfit、asset、skin、login、logout、settings。
- 用户名变更保留旧 slug 历史；用户注销/封禁按 tombstone/保留期策略处理，避免历史链接被重新分配给其他用户。
- 游客可在 Studio 本地创作；登录后提供显式迁移，不得静默覆盖云端项目。

### B. 预览与试穿的统一规则

- 素材库独立浏览预览：只展示渲染后的单件服装/素材，不默认把人物渲染进每一张素材卡片。
- 衣橱/Studio 选装预览：一旦用户执行试穿、选装或加入搭配，立即显示人物穿上该单件装备的实时结果；没有导入 Skin 时使用默认人物底模，导入 Skin 后切换为用户皮肤并保留已穿戴装备。
- 完整搭配模式用于管理多件装备和组合，不是人物预览的开关。新增、替换、隐藏、移除任一装备都应立即更新人物。
- 这条规则优先于动画专项文档中“单件服装使用单件预览”的简写；后者只适用于素材库独立浏览，不适用于已经进入试穿流程的 Studio。

### C. 统一动画技术方案

- Motion for React（Framer Motion 的后继项目）作为 React UI 默认动画层，使用 motion/react；适用于导航、菜单、弹窗、抽屉、Tabs、列表与轻量状态变化。
- GSAP + @gsap/react 仅用于 Motion/CSS 难以表达的复杂时间线、引导流程或少量品牌叙事；按路由懒加载，使用 context 并在组件清理时 revert。
- CSS transition/keyframes 用于颜色、边框、透明度等微交互；Lottie 仅在已有真实动画素材且确有价值时可选，不作为基础依赖。
- 依赖必须通过仓库当前 npm 版本执行安装并同步提交 package-lock.json；禁止手工编辑锁文件或只改 package.json。
- Next.js App Router 中保持 Server Component 默认；只把真正需要交互动画的最小组件标记为 Client Component。简单服务端动画优先评估 motion/react-client。
- 不允许 Motion 与 GSAP 同时控制同一元素的同一属性；避免动画 skinview3d/Three.js canvas、模型根节点或指针绘制循环，3D 变换继续由 3D 引擎负责。
- 尊重 prefers-reduced-motion；动画关闭时核心功能仍立即可用。优先 transform/opacity，避免大面积阴影、滤镜、布局属性和长时间主线程动画。
- 动画时长基线：微交互 100–160ms，菜单/弹窗 160–220ms，内容布局 180–260ms，品牌/引导 350–700ms（仅在确有帮助时）。
- 实施顺序：共享 tokens/基础组件 → 导航与账户菜单 → Dialog/Drawer/Tabs → Studio 选中反馈和面板 → AI 进度与结果反馈 → 可选 GSAP 品牌/引导场景。
- 进度动画必须反映真实后端状态，禁止伪造生成进度；编辑器画布、3D 预览的交互响应不得因动画层变慢。

## 统一技术架构基线：PostgreSQL Only 与全栈工程规范（2026-11-06）

本节是 CDPC 的唯一技术决策基线；与历史章节冲突时，以本节及前文明确的最终产品决策为准。此处定义的是目标架构，不代表相关依赖或功能已经在仓库中安装、接入或验收。

### 1. 数据库：PostgreSQL Only

- PostgreSQL 是开发、测试、CI、Docker、预发布和生产环境唯一支持的数据库。
- Prisma 是唯一 ORM；只维护一份 PostgreSQL Prisma Schema 和一套 Migration。
- 统一使用 `DATABASE_URL`；删除 `DATABASE_PROVIDER` 多数据库切换设计。
- 不再支持 MySQL、SQLite，不再新增其 Schema、迁移、适配器、测试矩阵或文档承诺。
- 本地开发和 CI 使用 PostgreSQL 服务容器；测试环境与生产保持同一数据库类型和关键扩展/版本约束。
- 清理前必须盘点当前 main、各 PR 分支、Docker Compose、Dockerfile、CI、部署环境变量、Prisma 配置及生产数据。若生产或用户数据仍位于 MySQL/SQLite，先制定并演练 PostgreSQL 数据迁移、校验、回滚和备份恢复方案；不得直接删除旧数据或在没有验证的情况下切换生产连接。
- 数据库验收至少覆盖空库全量迁移、已有库升级、唯一约束、外键、事务/并发、索引、JSON/枚举字段、备份恢复和跨用户数据隔离。

### 2. 总体架构：模块化单体 + 独立异步 Worker

- Web 页面与常规业务 API 统一由 Next.js App Router 提供；禁止维护第二套 Vite 正式页面运行时。
- 采用模块化单体和清晰业务边界，现阶段不引入微服务/Kubernetes 作为默认架构。
- Next.js 负责页面、会话入口、轻量 API 编排；业务规则集中在服务层，不允许页面或客户端绕过服务层直接访问数据库。
- AI 图片生成、耗时文件处理、邮件发送等长任务通过异步任务接口执行，不阻塞 Web 请求。Redis/BullMQ 仅在实际任务量和部署需求确认后引入；未接入前不得在文档中声称已有队列能力。
- SWC 是 Next.js 的编译/转译工具，不等同于 PWA。PWA 由 manifest、Service Worker、缓存策略和安装体验组成。

### 3. 前端与状态管理

- 基础：Next.js App Router、React、TypeScript、SWC。
- UI：Mantine 作为常规组件库；Tailwind CSS v4 管理设计令牌和布局；Lucide React 统一图标。避免重复造组件。
- 状态：服务端数据缓存/请求状态优先采用 TanStack Query；跨组件编辑器状态可采用 Zustand；表单可采用 React Hook Form + Zod。引入前先检查现有依赖和实现，避免重复安装。
- 国际化：统一中文/英文资源与路由策略，不在组件中散落硬编码文案。
- Next.js Server Component 默认；只有需要浏览器交互、Canvas、WebGL 或客户端状态的最小边界使用 Client Component。
- PWA 缓存默认不得缓存登录态 API、私有项目、用户文件和 AI 私有结果；离线草稿不代表云端保存成功，恢复网络后必须处理冲突。

### 4. 后端、API 与数据契约

- Next.js Route Handlers 负责 HTTP 接口；业务服务层承载权限、状态转换和业务规则；Prisma 负责持久化。
- 使用 Zod 或现有等价方案验证请求、环境变量和外部模型响应；统一错误结构、错误码、分页和幂等策略。
- 所有资源授权以不可变 userId 为准；username/slug、客户端 ownerId 和 URL 参数不能作为权限凭据。
- 对 Project、Asset、Outfit、Publication、AI Job 等明确状态机、所有权、版本、可见性、授权和删除生命周期。
- 文件上传验证 MIME、文件签名、大小、像素尺寸和内容；采用对象存储/S3 兼容接口时，访问 URL、删除和引用清理均由服务端控制。
- 对上传、保存、发布、导出、AI 任务和支付预留幂等键及审计记录。

### 5. CDPC 创作引擎专项

- 2D：64×64 Skin UV、Classic/Slim、内外层、透明像素、图层、选区、撤销/重做、PNG 导入导出；大规模像素处理可在验证后使用 Web Worker。
- 3D：复用仓库现有并验证通过的 skinview3d/Three.js 体系，不并行引入第二套 3D 引擎；人物、装备槽位、纹理映射、材质、动画和相机职责清晰。
- 服装类别必须独立：披肩、外套、上衣、裤子、鞋子、帽子、披风；披风与鞘翅分别管理。
- 素材库独立预览单件；进入 Studio 试穿/选装后立即显示人物穿戴结果。完整搭配只负责组合管理，不是人物预览开关。
- AI：文本/图片生成通过模型适配层统一接入；记录供应商、模型、参数、任务状态、成本、失败原因和重试次数。生成结果进入统一 Asset 流程，不建立孤立格式。
- 导出必须区分标准 Minecraft Skin PNG 与独立服装/披风/鞘翅纹理、搭配 JSON、项目备份；不得误导用户认为披风/鞘翅可写入标准 Skin PNG。

### 6. 文件、缓存与搜索

- 文件存储优先评估 Cloudflare R2 或兼容 S3 的对象存储；选型需结合现有部署、成本、访问控制和迁移成本，未验证前不声称已接入。
- 数据库保存元数据与引用，不把大型原始图片作为常规业务记录直接堆入数据库。
- 缩略图、纹理校验、格式转换和清理可异步处理；CDN 只缓存公开且可缓存的资源。
- 早期搜索优先使用 PostgreSQL 能力；只有搜索规模和质量需求证明必要时再引入独立搜索服务。
- IndexedDB 可用于本地草稿和离线恢复，但必须定义容量、版本、清理、账号切换隔离和冲突同步策略。

### 7. 认证、安全与管理

- 统一 Auth.js/现有认证实现；OAuth 提供商按实际配置启用，不把环境变量展示页视为认证已接通。
- 服务端 RBAC + 资源所有权检查；管理后台所有敏感操作必须服务端授权。
- 基础安全覆盖 CSRF、XSS、SQL 注入防护、CSP、安全 Cookie、速率限制、暴力登录保护、上传校验、敏感配置保护和审计日志。
- 邮件、OAuth、对象存储、AI 供应商密钥只能在服务端使用；错误日志不得泄漏密钥、令牌或私有文件 URL。
