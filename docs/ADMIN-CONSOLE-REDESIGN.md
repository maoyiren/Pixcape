# CDPC 管理后台重构方案

> 状态：实施基线。目标不是把更多表单塞进总览，而是建立独立、可扩展的管理控制台。

## 1. 交互与信息架构

采用 WordPress 风格的后台壳层：桌面端固定可折叠侧边栏 + 顶部管理栏 + 面包屑 + 独立内容页；移动端改为抽屉式导航，内容区单列。每个模块有自己的 URL、加载状态、成功/失败反馈和权限校验。总览只展示待办、系统状态和快捷入口，不放大段配置表单。

建议模块：

- 总览：用户/创作者/作品概览、待审核事项、服务健康、最近管理活动。
- 用户：用户列表、搜索筛选、用户详情、角色/状态、登录方式、关联账号、封禁/解封、会话撤销。
- 内容：皮肤/服装/披肩/披风素材、作品、举报、审核队列、版权与归属信息。
- 创作者：申请审核、创作者资料、作品与违规记录。
- 登录与身份：OAuth 提供商、邮箱登录、注册策略、邮箱验证、回调与会话策略。
- AI 服务：Gemini、OpenAI、OpenRouter、火山引擎 Seedream、DeepSeek，以及模型、API 地址、默认模型、密钥状态与连接测试。
- 邮件服务：SMTP/邮件供应商、发件人、验证邮件模板、连接测试。
- 存储与 CDN：本地/S3 兼容存储、对象桶、公开资源域名、上传限制。
- 平台集成：Discord、GitLab、Twitch 等可选 OAuth/社区集成；支付、统计、反滥用/CAPTCHA 等后续接入。
- 系统：站点基础信息、功能开关、维护模式、限流、备份/恢复、健康检查。
- 安全：管理员、权限、登录历史、审计日志、密钥轮换与安全事件。

## 2. 第三方登录配置

第一批支持 Google、Apple、GitHub、Microsoft；预留 Discord、GitLab、Twitch。每个提供商单独配置：

- 启用/停用、显示名称、Client ID、Client Secret、授权范围。
- 自动生成并展示精确回调地址，复制按钮。
- 配置状态（未配置/已配置/待验证/连接失败）、最近测试时间和安全错误摘要。
- Client Secret 只写入服务端加密存储；读取时只返回“已设置”状态，不返回明文；留空表示保留，明确操作才清除。
- 配置保存后必须验证回调域名、授权端点和必要字段；未通过验证时不能对用户开放该登录方式。
- OAuth 凭据不应写入公开配置、客户端 bundle、URL、日志或审计详情。

已实现的动态配置流程：NextAuth handler 与服务端 session 读取统一调用 `getAuthOptions()`；该函数在每次请求时从数据库读取 Provider 设置并解密 Client Secret，再构建 GitHub、Google、Microsoft 和 Apple Provider。登录页按同一组设置展示可用登录方式。环境变量保留为数据库配置缺省时的回退；数据库显式禁用项优先级最高。配置更新即时影响后续请求，不依赖单实例内存缓存。

## 3. 后台地址与访问安全

- 公开导航、头像菜单、页脚、站点 sitemap 和普通页面都不显示后台地址；已从头像菜单移除“管理后台”入口。
- 将内部路由从 `/admin` 迁移到部署时配置的专用路径（通过 `CDPC_ADMIN_PATH` 设置），旧路径返回 404，不做公开跳转或提示新地址。
- 路径隐藏只作为降低扫描噪声的措施，绝不能替代权限：每个页面、Server Action、Route Handler 都必须重新验证数据库中的 ACTIVE + ADMIN 状态。
- 后台禁用搜索引擎索引，设置 noindex；避免在页面源码、公开 API、客户端日志中泄露内部路径。
- 管理员登录增加独立限流；后续支持 TOTP/Passkey 和可信设备；敏感配置变更要求二次确认。
- 所有写操作记录操作者、目标、时间、结果和变更摘要；绝不记录密码、OAuth Secret、API Key 或完整连接字符串。

## 4. 移动端控件规范

- 保存、测试、启用、删除等按钮按内容宽度显示，不得默认占满屏幕。
- 同一行按钮允许换行；危险操作独立分组，主要操作与次要操作视觉区分。
- 表单字段宽度 100%，按钮宽度 auto；触控高度 40–44px，窄屏不横向溢出。
- 表格改为卡片或可横向滚动容器；侧边栏改抽屉；顶部操作区允许换行。
- 成功/失败提示在表单附近显示，避免只依赖页面顶部 query string。

### 已完成（当前分支）

- 从公共头像菜单和站点导航中移除后台入口。
- 新增独立 `app/admin/layout.tsx` 后台壳层：侧边栏分组、顶部管理栏、管理员身份提示、返回站点入口；所有后台子页面由同一壳层承载。
- 新增 `app/admin/admin.css`：桌面侧栏布局、移动端横向菜单、窄屏适配、表单按钮按内容宽度显示、后台页面 noindex。
- 现有总览、用户、审计和统计页面均继续保留各自的 `requireRole('ADMIN')` 校验；后台 layout 额外进行一次入口校验。
- 保留原有 AI 配置和用户管理业务逻辑，没有用演示表单替换实际数据库操作。
- 新增登录与身份配置模块：支持 GitHub、Google、Microsoft、Apple 的数据库 Client ID / 加密 Client Secret、启用/禁用与 Microsoft Tenant 设置；Provider 在 NextAuth handler 与 session 中动态加载。
- 新增系统健康独立页，执行数据库、认证密钥、NEXTAUTH_URL 与 AI API 轻量探测。
- 新增邮件、存储、平台集成、安全独立页面；SMTP 配置接入 NextAuth Email Provider，登录限流阈值由数据库设置动态读取。
- 后台 layout 导航已加入登录与身份、系统健康独立入口；ReactNode 类型改为显式类型导入。

### 尚未完成 / 不得视为已上线

- 存储和平台集成页面目前完成独立配置、加密保存与审计，但尚未接入实际对象存储驱动和 Webhook 投递器；不能把保存状态视为服务已启用。
- OAuth Provider 配置已动态接入 NextAuth 初始化、登录页可用 Provider 列表与 callback handler；仍需真实 OAuth 应用凭据验证完整授权往返。
- 自定义后台路径和旧 `/admin` 的 404 由 `proxy.ts` 实现；部署时必须设置并持久化 `CDPC_ADMIN_PATH`，并完成生产反向代理与浏览器验证。
- 用户详情、内容审核、创作者管理、AI 服务、邮件服务、平台集成、存储/CDN、安全等完整页面和细粒度权限仍待实现。
- 尚未完成本地构建、lint、E2E、移动端浏览器及生产环境验证。

## 6. 安全实施约束

- 后台路径隐藏只能降低扫描噪声；所有页面、Server Actions 和 Route Handlers 必须独立检查数据库中的 ACTIVE + ADMIN 状态。
- 不要将 OAuth Client Secret、API Key、SMTP 密码或连接字符串回传浏览器，也不得写入日志/审计详情。
- OAuth 动态配置在 provider 初始化、登录页 provider 列表、回调和多实例缓存失效机制未同时打通前，不开放“动态启用”开关。
